Entrada Atmosférica: Observabilidad y Evaluación

Los 7 minutos del terror. Durante la entrada atmosférica nadie en la Tierra puede intervenir en tiempo real: solo queda observar la telemetría y confiar en que el diseño aguanta. Lo mismo pasa con un agente en producción. Instrumenta Control de Misión con OpenTelemetry para ver exactamente qué hizo en cada turno, y evalúa sus respuestas con Azure AI Evaluation para saber si la calidad se sostiene.

El agente sigue siendo el Control de Misión simulado de las fases anteriores, con la misma tool de telemetría de TRANSIT. Lo real aquí es la instrumentación (OpenTelemetry) y la evaluación (Azure AI Evaluation); los datos de la misión siguen siendo inventados.

Preparación del Entorno

Para esta fase necesitas lo mismo que en las anteriores (Python 3.12+, uv y un recurso de Azure OpenAI con gpt-5-mini) más el SDK de OpenTelemetry y el paquete de evaluación de Azure AI. A diferencia de APPROACH, ningún paquete de esta fase es beta.

Versiones: agent-framework-openai 1.18.2 (agent-framework-core 1.26.0), opentelemetry-sdk, opentelemetry-exporter-otlp-proto-grpc (para enviar trazas al Aspire Dashboard en el Paso 2) y opentelemetry-exporter-otlp-proto-http (para la opción sin Docker del Paso 2, un Tempo de Grafana Cloud), azure-ai-evaluation y python-dotenv.

Docker (Desktop en macOS/Windows o Docker Engine en Linux) corriendo es opcional: solo lo necesitas si eliges la Opción 1 del Paso 2 (Aspire Dashboard). La Opción 2 (Grafana Cloud) no necesita Docker. El Paso 1 no necesita nada más que tu terminal.

Conceptos Clave

Instrumentación automática

El framework ya emite spans de cada invoke_agent, chat y execute_tool. No se agrega código para generarlos: solo se decide a dónde van.

Span y traza

Un span es una operación con inicio, fin y atributos. Una traza es el árbol de spans de un turno completo del agente.

configure_otel_providers()

Una sola llamada que lee las variables OTEL_EXPORTER_OTLP_* y arma los exportadores. Se usa una vez, al arrancar el programa.

Evaluador

Una función de azure-ai-evaluation que puntúa una respuesta. Se llama sola, o en lote sobre un dataset con evaluate().

Paso 1 · Observabilidad local: ver trazas en la consola

Carpeta chapter01_observability. Control de Misión ya emite telemetría de OpenTelemetry por sí solo; lo único que falta es decirle a dónde mandarla. La forma más simple, sin ninguna infraestructura, es imprimirla en tu propia terminal.

chapter01_observability/mission_control.py reutiliza la tool get_telemetry de TRANSIT, para tener un turno con llamada a tool y así ver más de un tipo de span: 

import os
from typing import Annotated

from dotenv import load_dotenv
from agent_framework import Agent, tool
from agent_framework.openai import OpenAIChatCompletionClient

load_dotenv()  # carga las variables del .env (lo busca subiendo de carpeta)

INSTRUCTIONS = (
    "Eres el Control de Misión de una expedición a Marte "
    "y das informes técnicos a la tripulación. Usa terminología espacial. "
    "Responde siempre en una o dos líneas. "
    "Si no tienes un dato, dilo; no lo inventes."
)

TELEMETRY = {
    "propulsion": "Tanques al 82%, motores principales nominales",
    "energia": "Baterías al 91%, paneles solares generando 12 kW",
    "soporte_vital": "O2 21%, CO2 400 ppm, presión de cabina nominal",
}


@tool
def get_telemetry(
    system: Annotated[str, "Sistema a consultar: propulsion, energia o soporte_vital"],
) -> str:
    """Devuelve la telemetría actual de un sistema de la nave."""
    return TELEMETRY.get(system, "Sistema desconocido")  # dato simulado


def create_mission_control() -> Agent:
    client = OpenAIChatCompletionClient(
        model=os.getenv("AZURE_OPENAI_CHAT_COMPLETION_MODEL"),
        azure_endpoint=os.getenv("AZURE_OPENAI_ENDPOINT"),
        api_key=os.getenv("AZURE_OPENAI_API_KEY"),
    )
    return Agent(
        client=client,
        name="MissionControl",
        instructions=INSTRUCTIONS,
        tools=[get_telemetry],
    )

1.1 · configure_otel_providers(): una llamada, al arrancar

configure_otel_providers() lee las variables de entorno estándar de OpenTelemetry (OTEL_EXPORTER_OTLP_*) y las propias del framework (ENABLE_CONSOLE_EXPORTERS, ENABLE_SENSITIVE_DATA) y arma los exportadores. Se llama una sola vez, al principio del programa, antes de correr el agente.

Código del script chapter01_observability/step1_console_exporter.py:

import asyncio

from agent_framework.observability import configure_otel_providers, get_tracer
from opentelemetry.trace import SpanKind
from opentelemetry.trace.span import format_trace_id

from mission_control import create_mission_control


async def main() -> None:
    configure_otel_providers()  # lee ENABLE_CONSOLE_EXPORTERS y OTEL_EXPORTER_OTLP_* del .env

    with get_tracer().start_as_current_span(
        "Scenario: Telemetria de propulsion", kind=SpanKind.CLIENT
    ) as span:
        print(f"Trace ID: {format_trace_id(span.get_span_context().trace_id)}")

        mission_control = create_mission_control()
        response = await mission_control.run("¿Cómo está la propulsión? Consulta la telemetría.")
        print(f"CONTROL: {response.text}")


if __name__ == "__main__":
    asyncio.run(main())

Ejecución:

uv run chapter01_observability/step1_console_exporter.py

Cuando el turno completo corre, el exportador imprime un bloque como este por cada span del árbol. Para el ejemplo de arriba (un run() que pide una tool) vas a ver, en orden:

  • Scenario: Telemetria de propulsion: el span que abriste a mano, envuelve todo.
  • invoke_agent MissionControl: el turno completo del agente (gen_ai.operation.name=invoke_agent, gen_ai.agent.name=MissionControl).
  • chat <tu-implementacion> (dos veces): cada llamada al modelo (gen_ai.operation.name=chat), con gen_ai.usage.input_tokens y gen_ai.usage.output_tokens.
  • execute_tool get_telemetry: la ejecución de la tool (gen_ai.tool.name=get_telemetry).

Sin ENABLE_SENSITIVE_DATA, estos spans traen metadatos (nombres, duración, tokens), pero no el contenido de la conversación.

1.2 · Datos sensibles: ver el contenido real

Por defecto los spans no incluyen el texto de los mensajes ni los argumentos de las tools: solo metadatos. ENABLE_SENSITIVE_DATA=true (o enable_sensitive_data=True en el código) habilita que se capture contenido real. Microsoft recomienda esto solo en desarrollo o pruebas: ese contenido puede incluir datos del usuario.

Código del script chapter01_observability/step2_sensitive_data.py:

import asyncio

from agent_framework.observability import configure_otel_providers, get_tracer
from opentelemetry.trace import SpanKind
from opentelemetry.trace.span import format_trace_id

from mission_control import create_mission_control


async def main() -> None:
    # Además de leer el .env, forzamos datos sensibles y consola por si no están en el entorno
    configure_otel_providers(enable_sensitive_data=True, enable_console_exporters=True)

    with get_tracer().start_as_current_span(
        "Scenario: Telemetria con datos sensibles", kind=SpanKind.CLIENT
    ) as span:
        print(f"Trace ID: {format_trace_id(span.get_span_context().trace_id)}")

        mission_control = create_mission_control()
        response = await mission_control.run("¿Cómo está la propulsión? Consulta la telemetría.")
        print(f"CONTROL: {response.text}")


if __name__ == "__main__":
    asyncio.run(main())

Ejecución:

uv run chapter01_observability/step2_sensitive_data.py

Con enable_sensitive_data=True, el span execute_tool get_telemetry ahora trae gen_ai.tool.call.arguments ({"system": "propulsion"}) y gen_ai.tool.call.result (la telemetría simulada); los spans de chat incluyen el texto enviado al modelo y su respuesta. Sin esta variable, nada de eso aparece: solo que una tool llamada get_telemetry se ejecutó, cuánto tardó y si falló.

Paso 2 · Ver las trazas en una interfaz

Carpeta chapter01_observability (mismo capítulo). La consola sirve para confirmar que algo se emite, pero para explorar una traza —abrir cada span, ver su duración, comparar turnos— hace falta una interfaz. configure_otel_providers() no cambia entre opciones: solo cambian las variables OTEL_EXPORTER_OTLP_* en el .env.

2.1 · Opción 1: Aspire Dashboard (con Docker)

El Aspire Dashboard es una opción local y gratuita: recibe trazas por OTLP y las muestra en el navegador, sin ninguna cuenta de Azure.

Levanta el Aspire Dashboard con un solo comando (necesitas Docker corriendo):

docker run -d --name mars-aspire -p 18888:18888 -p 4317:18889 mcr.microsoft.com/dotnet/aspire-dashboard:latest

Descomenta OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317 en tu .env (ya está en la plantilla). No hace falta cambiar ni una línea de código: el mismo configure_otel_providers() del Paso 1 ya lee esa variable y, además de (u opcionalmente en vez de) la consola, envía las trazas por OTLP al Aspire Dashboard.

Código del script chapter01_observability/step3_otlp_aspire.py (idéntico a step1, la diferencia está en el .env):

import asyncio

from agent_framework.observability import configure_otel_providers, get_tracer
from opentelemetry.trace import SpanKind
from opentelemetry.trace.span import format_trace_id

from mission_control import create_mission_control


async def main() -> None:
    configure_otel_providers()  # con OTEL_EXPORTER_OTLP_ENDPOINT en el .env, también exporta por OTLP

    with get_tracer().start_as_current_span(
        "Scenario: Telemetria via Aspire", kind=SpanKind.CLIENT
    ) as span:
        print(f"Trace ID: {format_trace_id(span.get_span_context().trace_id)}")

        mission_control = create_mission_control()
        response = await mission_control.run("¿Cómo está la propulsión? Consulta la telemetría.")
        print(f"CONTROL: {response.text}")


if __name__ == "__main__":
    asyncio.run(main())

Ejecución:

uv run chapter01_observability/step3_otlp_aspire.py

Abre http://localhost:18888 en el navegador. En la pestaña Traces busca la traza con el Trace ID que imprimió el script: vas a ver el mismo árbol de spans del Paso 1 (invoke_agent → chat → execute_tool → chat), pero ahora navegable, con la duración de cada uno y sus atributos a un clic.

Opción 2: sin Docker, un Tempo de Grafana Cloud por OTLP (clic para ver detalles)

Si no quieres usar Docker, Grafana Cloud tiene un nivel gratuito con Tempo (su backend de trazas) ya incluido. Sigue siendo solo variables de entorno: ni step3_otlp_aspire.py ni configure_otel_providers() cambian una línea.

  1. Crea una cuenta gratis en Grafana Cloud y entra a tu stack.
  2. Ve a Connections → Add new connection → OpenTelemetry (OTLP) y copia el endpoint OTLP y las credenciales que te da (usuario/instance ID y una API key o token).
  3. Con esos dos datos arma un header Authorization con autenticación básica: Basic <base64(usuario:token)>. La mayoría de los sistemas operativos traen un comando para codificar en base64, por ejemplo echo -n "usuario:token" | base64 en Linux/macOS.

Variables de entorno (reemplazan, no se suman, a las de la Opción 1):

OTEL_EXPORTER_OTLP_ENDPOINT=https://otlp-gateway-<region>.grafana.net/otlp
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
OTEL_EXPORTER_OTLP_HEADERS=Authorization=Basic <tu-token-en-base64>

Grafana Cloud solo acepta OTLP por HTTP, no por gRPC: por eso cambia OTEL_EXPORTER_OTLP_PROTOCOL. Esta fase ya instala opentelemetry-exporter-otlp-proto-http junto con el exportador gRPC que usa la Opción 1, así que no hace falta instalar nada más.

Ejecuta el mismo script de siempre:

uv run chapter01_observability/step3_otlp_aspire.py

Entra a tu stack de Grafana Cloud, abre Explore, elige el datasource de Tempo y busca por el Trace ID que imprimió el script. El árbol de spans es el mismo que en el Aspire Dashboard; lo único que cambió fue a dónde apunta configure_otel_providers().

Paso 3 · Evaluación básica con Azure AI Evaluation

Carpeta chapter02_evaluation. Observabilidad dice qué pasó en un turno; evaluación dice si la respuesta fue buena. azure-ai-evaluation trae evaluadores listos para usar: unos no necesitan modelo (comparan texto contra texto), otros usan un modelo como juez.

3.1 · F1ScoreEvaluator: sin modelo, 100% local

F1ScoreEvaluator compara la respuesta contra una respuesta de referencia (ground_truth) por superposición de palabras: no llama a ningún modelo, así que corre sin credenciales ni costo.

Código del script chapter02_evaluation/step1_f1_score.py:

from azure.ai.evaluation import F1ScoreEvaluator

f1_score = F1ScoreEvaluator(threshold=0.5)

result = f1_score(
    response="Propulsión nominal: tanques al 82%, motores principales en estado nominal.",
    ground_truth="Tanques al 82%, motores principales nominales.",
)
print(result)

Ejecución:

uv run chapter02_evaluation/step1_f1_score.py

Salida real:

{'f1_score': 0.625, 'f1_score_score': 0.625, 'f1_score_passed': True, 'f1_score_result': 'pass', 'f1_score_reason': None, 'f1_score_status': 'completed', 'f1_score_threshold': 0.5, 'f1_score_properties': None}

f1_score es la puntuación (0 a 1); f1_score_passed/f1_score_result comparan contra el threshold que le diste al crear el evaluador. f1_score_reason queda en None porque esta métrica no razona, solo cuenta palabras compartidas.

3.2 · RelevanceEvaluator y CoherenceEvaluator: con un modelo como juez

Estos evaluadores no necesitan una respuesta de referencia: le piden a un modelo (el mismo recurso de Azure OpenAI de esta fase) que juzgue la respuesta. model_config usa el mismo TypedDict en ambos evaluadores.

Código del script chapter02_evaluation/step2_relevance_and_coherence.py:

import asyncio
import os

from azure.ai.evaluation import AzureOpenAIModelConfiguration, CoherenceEvaluator, RelevanceEvaluator

from mission_control import create_mission_control

MODEL_CONFIG: AzureOpenAIModelConfiguration = {
    "azure_deployment": os.getenv("AZURE_OPENAI_CHAT_COMPLETION_MODEL"),
    "azure_endpoint": os.getenv("AZURE_OPENAI_ENDPOINT"),
    "api_key": os.getenv("AZURE_OPENAI_API_KEY"),
}


async def main() -> None:
    query = "¿Cómo está la propulsión? Consulta la telemetría."

    mission_control = create_mission_control()
    response = await mission_control.run(query)
    print(f"CONTROL: {response.text}")

    relevance = RelevanceEvaluator(model_config=MODEL_CONFIG)
    coherence = CoherenceEvaluator(model_config=MODEL_CONFIG)

    print("Relevancia:", relevance(query=query, response=response.text))
    print("Coherencia:", coherence(query=query, response=response.text))


if __name__ == "__main__":
    asyncio.run(main())

Ejecución:

uv run chapter02_evaluation/step2_relevance_and_coherence.py

Cada evaluador devuelve un diccionario con la misma forma que F1ScoreEvaluator (relevance/coherence, su versión _result contra el threshold, y esta vez también relevance_reason/coherence_reason con la justificación del modelo juez, en una escala de 1 a 5).

3.3 · evaluate(): evaluación en lote sobre un dataset

Para evaluar muchas respuestas a la vez, evaluate() lee un archivo JSONL, corre los evaluadores que le pases sobre cada fila y guarda un resumen. No necesita ningún proyecto de Azure AI: con data y evaluators alcanza para correr todo en local.

Dataset de ejemplo chapter02_evaluation/data.jsonl (una fila por línea):

{"response": "Propulsión nominal: tanques al 82%, motores principales en estado nominal.", "ground_truth": "Tanques al 82%, motores principales nominales."}
{"response": "No tengo ese dato en la telemetría actual.", "ground_truth": "Baterías al 91%, paneles solares generando 12 kW."}

Código del script chapter02_evaluation/step3_batch_evaluate.py:

from azure.ai.evaluation import F1ScoreEvaluator, evaluate

result = evaluate(
    data="data.jsonl",
    evaluators={"f1_score": F1ScoreEvaluator(threshold=0.5)},
    output_path="eval_results.json",
)

print("Métricas agregadas:", result["metrics"])
print("Primera fila:", result["rows"][0])

Ejecución:

uv run chapter02_evaluation/step3_batch_evaluate.py

Salida real (recortada):

Métricas agregadas: {'f1_score.f1_score': 0.3125, 'f1_score.f1_score_score': 0.3125, 'f1_score.f1_score_passed': 0.5, 'f1_score.binary_aggregate': 0.5}
Primera fila: {'inputs.response': 'Propulsión nominal: ...', 'inputs.ground_truth': 'Tanques al 82%, ...', 'outputs.f1_score.f1_score': 0.625, 'outputs.f1_score.f1_score_passed': True, ...}

result["metrics"] promedia cada métrica sobre todas las filas (f1_score_passed promediado da la tasa de aprobación: 0.5 significa que la mitad de las filas pasó el threshold). result["rows"] trae el detalle fila por fila, con los inputs.* originales y los outputs.<evaluador>.* de cada evaluador. evaluate() también escribe el mismo detalle en eval_results.json. Para usar RelevanceEvaluator/CoherenceEvaluator en lote, agrégalos al diccionario de evaluators y agrega query a cada fila del dataset.
