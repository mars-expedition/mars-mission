Aproximación: Memoria Persistente

Marte en el horizonte. La maniobra de aproximación dura varios días y Control de Misión se reinicia entre turno y turno: necesita recordar a la tripulación aunque el proceso termine. Dale memoria que sobrevive a un reinicio con Redis (o un archivo local) y memoria semántica con Mem0, que recuerda hechos aunque la conversación sea otra.

En esta fase el agente sigue siendo el Control de Misión simulado de las fases anteriores. La comandante (Ana Torres), la nave Quilla-7 y la telemetría son inventadas: lo real aquí es la infraestructura de memoria (Redis, archivo, Mem0), no los datos de la misión.

Preparación del Entorno

Para esta fase necesitas lo mismo que en TRANSIT (Python 3.12+, uv y un recurso de Azure OpenAI con gpt-5-mini) más dos cosas nuevas:

  • Una implementación de embeddings en el mismo recurso de Azure OpenAI, por ejemplo text-embedding-3-small: la usa Mem0 para buscar memorias por similitud.
  • Docker (Desktop en macOS/Windows o Docker Engine en Linux) corriendo, para levantar Redis en un contenedor. Si no quieres usar Docker, el Paso 1 trae una opción libre sin él.

Esta fase usa dos paquetes oficiales del framework que todavía son beta, agent-framework-redis y agent-framework-mem0, que a su vez requieren una versión más reciente de agent-framework-core que las fases anteriores. Versiones: agent-framework-openai 1.18.2 (agent-framework-core 1.26.0), agent-framework-redis y agent-framework-mem0 1.0.0b261112, mem0ai 2.2.1 (instala qdrant-client como dependencia, el vector store local que usa Mem0) y python-dotenv. El pyproject.toml ya trae [tool.uv] prerelease = "allow", así que no hace falta ninguna bandera especial al instalar; también fija httpx<1.0 (sin ese tope, el permiso de prerelease deja pasar un httpx 1.0 preliminar que rompe Mem0) y agrega azure-identity (el llm/embedder azure_openai de Mem0 lo importan siempre, pero mem0ai solo lo declara bajo un extra que no instalamos).

El archivo .env tiene tu clave: no lo subas al repositorio. Cada capítulo tiene un mission_control.py con ayudantes (crea el agente y la memoria) y sus stepN_*.py, que es donde está lo que se enseña.

Conceptos Clave

Memoria de sesión

session.state vive en la memoria del proceso (lo visto en TRANSIT): se pierde en cuanto el programa termina.

ContextProvider

Clase del framework con dos ganchos: before_run (antes de llamar al modelo) y after_run (después). Se registra con context_providers=[...] al crear el Agent.

RedisHistoryProvider

Un ContextProvider que carga y guarda el historial de la sesión en Redis automáticamente: no hay que serializar nada a mano.

Mem0ContextProvider

Otro ContextProvider, de agent-framework-mem0: busca hechos relevantes antes del turno y los guarda después, usando Mem0 por debajo.

FileSessionStore

Alternativa del framework sin Redis: guarda el AgentSession completo (estado y todo) como un archivo JSON local.

Paso 1 · Persistencia con Redis

Carpeta chapter01_persistent_memory. session.state vive en la memoria del proceso: si el programa de Control de Misión se reinicia entre un día de aproximación y el siguiente, la sesión empieza vacía, igual que en TRANSIT sin sesión.

Código del script chapter01_persistent_memory/step1_without_persistence.py. Cada «día» crea un agente y una sesión nuevos, simulando dos ejecuciones separadas del mismo programa:

import asyncio

from mission_control import create_mission_control


async def run_day(label: str, message: str) -> None:
    # cada "día" es una ejecución nueva del programa: agente y sesión desde cero
    mission_control = create_mission_control()
    session = mission_control.create_session()

    print(f"[{label}] {message}")
    response = await mission_control.run(message, session=session)
    print(f"[{label}] CONTROL: {response.text}")
    print()


async def main() -> None:
    await run_day("Día 1", "Soy la comandante Ana Torres y mi nave se llama Quilla-7.")
    await run_day("Día 2", "¿Cómo se llama mi nave?")  # proceso nuevo: no recibe el día anterior


if __name__ == "__main__":
    asyncio.run(main())

Ejecución:

uv run chapter01_persistent_memory/step1_without_persistence.py

Salida de ejemplo (el texto del modelo cambia en cada ejecución):

[Día 1] Soy la comandante Ana Torres y mi nave se llama Quilla-7.
[Día 1] CONTROL: Registrado, comandante Ana Torres; nave Quilla-7 anotada en el manifiesto de Control de Misión.

[Día 2] ¿Cómo se llama mi nave?
[Día 2] CONTROL: Control de Misión no tiene registrado el nombre de su nave en esta sesión; indique el callsign o la matrícula para confirmarlo.

En un caso real esto serían dos ejecuciones de uv run en días distintos, no dos funciones dentro del mismo script.

1.1 · RedisHistoryProvider: persistencia sin guardar nada a mano

agent-framework-redis trae RedisHistoryProvider, un ContextProvider listo para usar: antes del turno carga el historial de la sesión desde Redis, y después del turno lo guarda. No hay que leer ni escribir session.state a mano; solo registrarlo con context_providers=[...] al crear el agente.

El ayudante chapter01_persistent_memory/mission_control.py expone create_redis_history_provider() y deja que create_mission_control() reciba cualquier lista de context_providers: 

import os

from dotenv import load_dotenv
from agent_framework import Agent, ContextProvider
from agent_framework.openai import OpenAIChatCompletionClient
from agent_framework.redis import RedisHistoryProvider

load_dotenv()  # carga las variables del .env (lo busca subiendo de carpeta)

INSTRUCTIONS = (
    "Eres el Control de Misión de una expedición a Marte "
    "y das informes técnicos a la tripulación. Usa terminología espacial. "
    "Responde siempre en una o dos líneas. "
    "Si no tienes un dato, dilo; no lo inventes."
)

APPLICATION_ID = "mars-mission-control"  # límite de aislamiento obligatorio para el historial con clave "scoped"


def create_redis_history_provider() -> RedisHistoryProvider:
    return RedisHistoryProvider(
        redis_url=os.getenv("REDIS_URL", "redis://localhost:6379"),
        application_id=APPLICATION_ID,
        agent_id="mission-control",
    )


def create_mission_control(context_providers: list[ContextProvider] | None = None) -> Agent:
    client = OpenAIChatCompletionClient(
        model=os.getenv("AZURE_OPENAI_CHAT_COMPLETION_MODEL"),
        azure_endpoint=os.getenv("AZURE_OPENAI_ENDPOINT"),
        api_key=os.getenv("AZURE_OPENAI_API_KEY"),
    )
    return Agent(
        client=client,
        name="MissionControl",
        instructions=INSTRUCTIONS,
        context_providers=context_providers,  # aquí engancha RedisHistoryProvider, Mem0ContextProvider, etc.
    )

1.2 · El mismo programa, dos ejecuciones, memoria que sobrevive

step2_with_redis_history.py usa un SESSION_ID fijo para identificar la conversación entre ejecuciones. Eso es todo: ni carga ni guarda nada explícitamente, lo hace RedisHistoryProvider solo.

Código del script chapter01_persistent_memory/step2_with_redis_history.py:

import asyncio

from mission_control import create_mission_control, create_redis_history_provider

SESSION_ID = "comandante-ana-torres"  # mismo id en cada ejecución -> mismo historial en Redis


async def run_mission_control(label: str, message: str) -> None:
    history_provider = create_redis_history_provider()  # antes del turno carga; después, guarda
    mission_control = create_mission_control(context_providers=[history_provider])
    session = mission_control.create_session(session_id=SESSION_ID)

    print(f"[{label}] {message}")
    response = await mission_control.run(message, session=session)
    print(f"[{label}] CONTROL: {response.text}")


async def main() -> None:
    await run_mission_control("Esta ejecución", "Soy la comandante Ana Torres y mi nave se llama Quilla-7.")


if __name__ == "__main__":
    asyncio.run(main())

[Esta ejecución] CONTROL: Registrado, comandante Ana Torres; nave Quilla-7 anotada en el manifiesto de Control de Misión.

El segundo proceso no comparte memoria RAM con el primero; lo que le permite recordar es el historial que RedisHistoryProvider guardó en Redis al terminar el primero, bajo la clave que arma a partir de application_id, agent_id y el session_id.

1.3 · Inspeccionar lo guardado

El historial se guarda como una lista de Redis bajo una clave con segmentos codificados (no un simple session:<id>). Para verla: 

docker exec -it mars-redis redis-cli --scan --pattern "chat_messages*"

Copia la clave que aparezca y lee su contenido:

docker exec -it mars-redis redis-cli lrange "<clave-copiada>" 0 -1
Sin Docker: FileSessionStore, la alternativa del framework sin Redis (clic para ver detalles)

agent_framework.FileSessionStore (todavía experimental, pero ya parte del paquete agent-framework-core, sin instalar nada adicional) guarda el AgentSession completo como un archivo JSON. Como no hay Redis para el historial, el agente usa su InMemoryHistoryProvider por defecto (el mismo de TRANSIT): el historial vive en session.state, y FileSessionStore persiste ese state entero.

Código del script chapter01_persistent_memory/step3_with_file_store.py:

import asyncio

from agent_framework import FileSessionStore

from mission_control import create_mission_control

SESSION_ID = "comandante-ana-torres"
store = FileSessionStore(".sessions")  # un archivo JSON por sesión en phases/05-approach/.sessions/


async def run_mission_control(label: str, message: str) -> None:
    mission_control = create_mission_control()  # sin context_providers: usa InMemoryHistoryProvider por defecto

    session = await store.get(SESSION_ID)  # None la primera vez
    if session is None:
        session = mission_control.create_session(session_id=SESSION_ID)
        print(f"[{label}] Sin memoria previa en el archivo")
    else:
        print(f"[{label}] Sesión recuperada del archivo")

    print(f"[{label}] {message}")
    response = await mission_control.run(message, session=session)
    print(f"[{label}] CONTROL: {response.text}")

    await store.set(SESSION_ID, session)  # persiste todo session.state para la próxima ejecución


async def main() -> None:
    await run_mission_control("Esta ejecución", "Soy la comandante Ana Torres y mi nave se llama Quilla-7.")


if __name__ == "__main__":
    asyncio.run(main())

Igual que con Redis: corre el script, luego cambia el mensaje a "¿Cómo se llama mi nave?" y vuelve a correrlo. El segundo proceso recupera la sesión completa desde .sessions/comandante-ana-torres.json.

Paso 2 · Memoria semántica con Mem0

Carpeta chapter02_semantic_memory. Redis en el Paso 1 guarda la conversación completa bajo un SESSION_ID: para recordar, hay que volver a cargar y reproducir todo ese historial. La memoria semántica guarda hechos ya resumidos (p. ej. «prefiere reportes en una línea») y los recupera por significado, no por sesión: sirven aunque la conversación sea otra. Es la misma idea de RAG de la fase ORBIT, pero la base de conocimiento es la propia conversación con la comandante.

chapter02_semantic_memory/mission_control.py configura AsyncMemory de Mem0 (el cliente OSS, async) para usar Azure OpenAI (el mismo recurso de chat y embeddings) como motor de extracción y búsqueda, y Qdrant embebido en disco como vector store: no necesita ningún servidor, todo queda en la carpeta mem0_db/. 

import os

from dotenv import load_dotenv
from agent_framework import Agent, ContextProvider
from agent_framework.openai import OpenAIChatCompletionClient
from mem0 import AsyncMemory

load_dotenv()  # carga las variables del .env (lo busca subiendo de carpeta)

INSTRUCTIONS = (
    "Eres el Control de Misión de una expedición a Marte "
    "y das informes técnicos a la tripulación. Usa terminología espacial. "
    "Responde siempre en una o dos líneas. "
    "Si no tienes un dato, dilo; no lo inventes."
)

CHAT_MODEL = os.getenv("AZURE_OPENAI_CHAT_COMPLETION_MODEL")
EMBEDDING_MODEL = os.getenv("AZURE_OPENAI_EMBEDDING_MODEL")
AZURE_ENDPOINT = os.getenv("AZURE_OPENAI_ENDPOINT")
AZURE_API_KEY = os.getenv("AZURE_OPENAI_API_KEY")

API_VERSION = "2024-10-21"


def _azure_config(deployment: str | None) -> dict:
    """Config de un modelo de Azure OpenAI para Mem0 (igual para el de chat y el de embeddings)."""
    return {
        "model": deployment,  # se envía como "model" en cada llamada a Azure OpenAI
        "azure_kwargs": {
            "azure_deployment": deployment,
            "azure_endpoint": AZURE_ENDPOINT,
            "api_key": AZURE_API_KEY,
            "api_version": API_VERSION,
        },
    }


MEM0_CONFIG = {
    "llm": {"provider": "azure_openai", "config": _azure_config(CHAT_MODEL)},
    "embedder": {
        "provider": "azure_openai",
        "config": {**_azure_config(EMBEDDING_MODEL), "embedding_dims": 1536},  # dimensiones de text-embedding-3-small
    },
    "vector_store": {
        "provider": "qdrant",
        "config": {
            "path": "./mem0_db",  # Qdrant embebido en disco: sin servidor, memoria semántica 100% local
            "collection_name": "mars_crew_memory",
            "embedding_model_dims": 1536,  # debe coincidir con las dimensiones del embedder
        },
    },
}


def create_memory() -> AsyncMemory:
    return AsyncMemory.from_config(MEM0_CONFIG)


def create_mission_control(context_providers: list[ContextProvider] | None = None) -> Agent:
    client = OpenAIChatCompletionClient(
        model=CHAT_MODEL,
        azure_endpoint=AZURE_ENDPOINT,
        api_key=AZURE_API_KEY,
    )
    return Agent(
        client=client,
        name="MissionControl",
        instructions=INSTRUCTIONS,
        context_providers=context_providers,
    )

2.1 · Guardar y buscar memorias, sin agente

Antes de mezclarlo con el agente, prueba AsyncMemory directamente: memory.add() llama al modelo para extraer los hechos relevantes del texto y los guarda como vectores; memory.search() devuelve los más parecidos a la pregunta, con un score de similitud. Nota que add() acepta user_id directo, pero search() exige pasarlo dentro de filters.

Código del script chapter02_semantic_memory/step1_store_and_search.py:

import asyncio

from mission_control import create_memory

USER_ID = "comandante-ana-torres"  # separa la memoria de cada persona


async def main() -> None:
    memory = create_memory()

    await memory.add(
        [
            {"role": "user", "content": "Soy la comandante Ana Torres y mi nave se llama Quilla-7."},
            {"role": "user", "content": "Prefiero los reportes en una sola línea, sin rodeos."},
        ],
        user_id=USER_ID,
    )  # Mem0 extrae los hechos relevantes de estos mensajes y los guarda como vectores

    results = await memory.search(
        "¿Cómo le gusta recibir los reportes a la comandante?",
        filters={"user_id": USER_ID},
    )
    for item in results["results"]:
        print(f"[{item['score']:.2f}] {item['memory']}")


if __name__ == "__main__":
    asyncio.run(main())

Ejecución:

uv run chapter02_semantic_memory/step1_store_and_search.py

Salida de ejemplo (los score varían según el modelo de embeddings):

[0.81] Prefiere los reportes en una sola línea, sin rodeos.
[0.52] Su nave se llama Quilla-7.

La memoria más relevante para la pregunta queda primero: Mem0 la encontró por significado, no porque fuera el mensaje más reciente.

2.2 · Mem0ContextProvider: el agente recuerda entre sesiones distintas

agent-framework-mem0 trae Mem0ContextProvider, otro ContextProvider listo para usar: antes del turno busca hechos relevantes en Mem0 y los agrega al contexto; después del turno guarda el nuevo intercambio. Separa el alcance de guardado (user_id/agent_id) del alcance de búsqueda (search_user_id/search_agent_id): si no configuras ningún search_*, no se recupera nada.

Código del script chapter02_semantic_memory/step2_agent_with_semantic_memory.py:

import asyncio

from agent_framework.mem0 import Mem0ContextProvider

from mission_control import create_memory, create_mission_control

USER_ID = "comandante-ana-torres"  # en producción sería el id real del usuario


async def main() -> None:
    memory = create_memory()  # AsyncMemory.from_config(...): 100% local
    mem0_provider = Mem0ContextProvider(
        mem0_client=memory,
        user_id=USER_ID,  # con quién se guarda cada hecho nuevo (after_run)
        search_user_id=USER_ID,  # de quién se recuperan hechos al empezar un turno (before_run)
    )

    # "Día 1": sesión nueva, memoria semántica vacía para esta comandante
    print("--- Día 1 ---")
    mission_control = create_mission_control(context_providers=[mem0_provider])
    session = mission_control.create_session()
    for message in (
        "Soy la comandante Ana Torres y mi nave se llama Quilla-7.",
        "Prefiero los reportes en una sola línea, sin rodeos.",
    ):
        print(f"COMANDANTE: {message}")
        response = await mission_control.run(message, session=session)
        print(f"CONTROL: {response.text}")
        print()

    # "Día 5": agente y sesión nuevos (como si el programa se hubiera reiniciado varias veces)
    print("--- Día 5: sesión nueva ---")
    mission_control = create_mission_control(context_providers=[mem0_provider])
    session = mission_control.create_session()
    message = "Dame el reporte de propulsión."
    print(f"COMANDANTE: {message}")
    response = await mission_control.run(message, session=session)
    print(f"CONTROL: {response.text}")


if __name__ == "__main__":
    asyncio.run(main())

Ejecución:

uv run chapter02_semantic_memory/step2_agent_with_semantic_memory.py

Salida de ejemplo:

--- Día 1 ---
COMANDANTE: Soy la comandante Ana Torres y mi nave se llama Quilla-7.
CONTROL: Registrado, comandante Ana Torres; nave Quilla-7 anotada en el manifiesto de Control de Misión.

COMANDANTE: Prefiero los reportes en una sola línea, sin rodeos.
CONTROL: Entendido, comandante; reportes en una sola línea a partir de ahora.

La sesión de «Día 5» es nueva: no tiene el historial de «Día 1» ni pasó por Redis ni por FileSessionStore. Aun así el agente responde en una línea, sin rodeos, y usando el nombre de la nave: lo recordó Mem0ContextProvider en before_run, no la sesión.
